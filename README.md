2026-09-08 / Codex。ローカルCPU試作。ユーザーの「とりあえずボクシングルールでつくってみる」に基づき、蹴りを除外して着手。時間方式の最終採用は未確定で、常時スローを試作の既定にした。

GitHub Pagesで遊べる静的プロトタイプ: https://aratama-ship-it.github.io/super-slow-kickboxing/

## 起動
ワークスペース直下から:

```sh
python3 -m http.server 8876 --bind 127.0.0.1 --directory "apps/game-app/super-slow-kickboxing"
```

ブラウザで http://127.0.0.1:8876/boxing/ を開く。ゲーム入口はindex.html。ES Modulesのためfile:で直接開かずHTTPで表示する。ゲーム本体は外部通信やアカウント設定を使わない。

## 実装した範囲
- 一人称3D、体積のあるマネキン、自分の赤い左右グローブ、青いグローブの相手、有限のリング。
- オーソドックス固定。身体と両足の向きを正面から45°傾け、左手・左肩・左足を前、右手・右肩・右足を後ろへ置く。ガード移動中と攻撃の溜めでも前後関係を保つ。構えデータは後の左右切替で差し替えられる境界にした。
- 左ジャブ、右ストレート、左右フック、左右アッパー。頭／胴を選択。頭狙いの左ジャブは拳中心の終点を従来より10cm下げ、額ではなく鼻から口付近へ向ける。左右の公平性を保つため自分と相手へ同じ値を使い、他のパンチと胴狙いの高さは変えない。構え中は左右の拳を各軸約1〜2cmの範囲で異なる周期・位相により動かし続ける。左ジャブ固有の引きや溜めは置かず、2.7 TUの固定tickから拳、左前足、腰、胸、頭、肩線を同時に始動する。前足は最大約10cm、腰は約3.5cm、胸は約5cm、頭は約4.5cm前進し、体幹を約4°回してから一緒に戻す。パーリングで攻撃腕が弾かれた場合も接触時の姿勢から構えへ戻る。後ろ足を構え位置へ残し、フォーム用の動きは選手本体の位置・射程・命中判定・CPUの観測条件を変えない。
- パンチの拳同士が0.20m以内で接触した場合、衝突力の弱い側の腕だけを4 TU弾く。弾かれた腕は攻撃・防御に使えず、強い側のパンチは続行する。同じ力なら双方を3 TU弾く仮ルール。
- 左右それぞれのパーリング／顔のブロッキング／お腹ブロッキング。顔のブロッキングでは両グローブを額の左右へつけ、肘を肋骨側へ畳んで脇を締める。自分の拳と前腕が実際に一人称視界の左右を覆い、中央だけが見える。暗転やビネットは使わない。顔とお腹のブロッキングは3 TUで切り替えて維持。攻撃・パーリング・弾かれ動作中の手は元のガードを使えない。
- パーリングは1回入力で準備0.18 TU → 真上から叩く0.55 TU → 戻り0.9 TU。現在のガード位置から横へ動かさず約5.5cm上げ、同じ左右位置のまま合計約8cm下へ落とす。現在検証中の左ジャブは着弾までの軌道を80%進んだ後、82.5%までの間に拳中心間0.24m以内へ入ったときだけ成立する。ジャブの軌道が見える2.7 TU後から入力でき、固定ケースは3.0 TUに入力して3.63 TU前後に接触する。右ストレートに対する左手パーリングは未検証のため、従来の70%条件を保持する。成功すると相手の拳は接触位置から約14cm前進しながら約18cm下へ外れ、攻撃腕だけを4 TU使えなくする。準備・戻りの隙は連打や同じ手の攻撃／防御切替で消せず、反対の手は独立して操作できる。空振りもスタミナ5を使い、終了後は元の顔／お腹ブロッキングへ戻る。顔のブロッキングは頭への全パンチを1ダメージで受け、お腹ブロッキングは胴へのパンチを無傷で受け、双方の腕を弾かない。必要な左右の手が合っている場合だけ成立する仮ルール。
- プレイヤーのパーリングが実際に接触した瞬間だけ、使った左右のグローブの上へ英字「PARRY」を720ms表示する。文字は12pxで、自分の赤グローブに対応する明るい赤。表示中はグローブの3D位置を画面座標へ投影して追従する。入力だけ、空振り、ブロッキング、CPU側だけの成功では表示しない。発光、画面揺れ、音は加えず、動き低減設定では文字の上下動を止めたまま同じ時間で消す。
- 始動中のフェイント、制動と戻り、次の技1件の予約と差替え・取消・期限。
- 前後の足運び、左右への頭位置の退避、射程、簡易的な拳と部位の接触。
- スタミナ、体力、同時ヒット、KO・時間切れ・引き分け。正式なボクシング採点ではない。
- 読み合いCPU、ジャブ練習、静止相手。CPUは公開された姿勢だけを0.25 TU遅れて観測し、左ジャブの軌道と頭狙いが見えてからパーリングまたはブロッキングを選ぶ。非公開入力や予約は参照しない。開始／停止／再戦。非表示・blurで練習を停止。
- 頭／胴の狙いは画面の二択に加え、左Shiftを1回押すたびに切り替わる。攻撃開始時と予約時の狙いを個別に保持するため、実行中の技を変えずに次のパンチだけ別部位へ予約できる。
- 狙い切替、パンチ、左右別の守り、足運び、頭移動、フェイント、一時停止の19操作を画面から変更できるキー設定。同じキーは既存操作と自動で入れ替え、ブラウザ内へ保存。初期設定へ戻せる。
- 初期キーは、狙い切替＝左Shift、攻撃＝J／K／U／I／M／,、守り＝H／L／Y／O／N／.、間合いと頭位置＝W／S／A／D、フェイント＝F、一時停止＝Space。既存の個別設定は保持し、新規利用時と「初期設定に戻す」を選んだ場合にこの配置を使う。
- 相手の選択欄に「組み合わせ検証」を追加。固定条件で1ケースだけ再生する。ケース01は顔中央への照準、構え中の両手の小動作、拳・前足・足腰・上体の同時始動、反応入力と接触、手の左右移動、ダメージ、両者の該当腕、全身の復帰を9項目で照合する。ケース02は5項目のまま。最初は「相手の左ジャブ × 右手パーリング」、本人が「この挙動で進める」を選んだ後だけ「相手の左ジャブ × 右手ブロッキング」へ進める。動作を変更するたびに旧採否を無効化する。`?lab=1`で検証画面を直接開ける。

## 制限と未実装
- 蹴り、オンライン、サウスポーへの構え切替、クリンチ、ダウンとカウント、正式採点は未実装。
- パーリングは各手で固定された小さい下方向の動作。上下／内外を自由に指定する操作、左右別の自由な手位置、キャッチ、スウェー、ダッキングは未実装。
- 攻撃は1件ずつ。左右のパンチを重ねる連係や、パンチ中に別入力で足運びを重ねる操作は許可していない。左ジャブ固有の前足同期は自動で行う。
- 動作時間・射程・威力・CPU方針はゲーム用仮値。格闘経験者による自然さ・面白さの確認は未実施。
- パンチ同士は拳の中心距離、身体への攻撃は拳位置と頭／胴の楕円体、ガードのモードで判定。腕全体の衝突、速度・質量・角度を含む自由物理ではない。
- 人体は自作のプリミティブによる体積モデル。腕は肩／肘／拳を結ぶ簡易リグで、実人体の関節角・骨長を拘束していない。本人校正前のフォーム。
- 対応検証の中心はPC。モバイルでも操作できるレイアウトだが実スマホの操作感・性能は未確認。
- キー設定は現在のブラウザと端末ごとに保存する。別ブラウザ・別端末への同期や設定ファイルの書き出しは未実装。
- 組み合わせ検証の機械判定は現在の仮ルールとの一致を示す。動作の自然さや競技としての妥当性は証明せず、本人の採否はブラウザ内だけに保存する。

## コードの境界
- core.mjs: ブラウザ非依存の戦闘規則、技データ、左右別の防御・弾かれ状態、共有する拳位置、公開観測、CPU。
- view.mjs: Three.js描画。表示用の拳位置はcore.mjsのvisualGloveLocal、接触判定はcore.mjsのgloveLocalを使い、小動作を判定から分離する。
- app.mjs: 入力、固定刻みの更新、停止、UI。世界時間とUI反応を分離。
- keymap.mjs: 19操作の既定キー、保存値の検証、表示名、重複時の入れ替え。
- scenario-lab.mjs: 検証ケースの固定条件、再生手順、接触時の観測、復帰条件、ケース別の機械判定。
- core.test.mjs: node標準の意味的なルール検証。
- keymap.test.mjs: キー設定の完全性、壊れた保存値からの復帰、重複キーの入れ替えを検証。
- scenario-lab.test.mjs: ケース順、パーリング時の片腕だけの弾かれ、ブロッキング時の双方非弾きを検証。
- vendor/: このワークスペースの既存three 0.185.1から2モジュールを複製。MITライセンスを同梱。出典 https://github.com/mrdoob/three.js/tree/r185 と公式 https://threejs.org/docs/ を参照。モデル・テクスチャの第三者素材は未使用。

## 引き継ぎ
最初に本人が判断するのは、ケース01「相手の左ジャブ × 右手パーリング」で、相手の左拳が額ではなく鼻から口付近へ向かうか、構え中の両手の小動作が自然でジャブ固有の予備動作を読みにくくしているか、拳・左前足・腰・上体が一体に見えるか、腰3.5cm・胸5cm・頭4.5cm・体幹4°が大きすぎないか、額につけた右手が内側へ入らず真上から小さく落ちるか、見てからの反応に感じるか、相手の拳の前進と下降量、4 TUの長さ。足腰連動には暫定的な肯定があり、グローブ上の赤い「PARRY」は本人確認済み。ケース01全体の採用後にケース02「右手ブロッキング」へ進む。顔ガードの両拳が額につき、肘を脇へ畳み、実際の拳と前腕で視界が十分狭く感じるかは本人確認待ち。続く候補は、逆手パーリング、早すぎるパーリング、遅すぎるパーリング、お腹ブロッキングの順。衝突力や接触距離の比較はジャブ防御の基準が固まってから行う。
